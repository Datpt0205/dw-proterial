Status: ready-for-agent (the 2026-10-03 follow-up below; the original scope
is done in `b5f990b`)
Blocked by: —

## What

- Declare `SalesCatalogPort` and `InboxPort` in `dw_sales/application/ports.py`.
- Implement `MockSalesCatalog` and `MockInbox` in `dw_sales/adapters/mock/`
  over fixture files: 6 fictional customers (one intra-group customer that
  sends one-sheet-per-page Excel POs), ~30 cable items with attributes,
  ~40 convert-list rows, ~25 quotations (incl. expired and LME-banded),
  12 months of LME copper, NOC/ESF status per customer.
- ~10 mock emails with generated attachments (xlsx, text PDF): clean PO,
  multi-sheet PO, PDF PO, price mismatch + unmapped code, revised PO,
  duplicate PO, quote request for a new item, quote request with target
  price, a non-PO email, a PO whose body carries a prompt-injection attempt.
- A script that regenerates the attachments from the fixtures.

## Acceptance

- Unit tests read every fixture through the ports.
- No real company or person names.

## Follow-up (2026-10-03)

The 02 and 03 amendments need these fixtures. All of them are fictional,
use `.example` domains, and are generated by
`generate_attachments.py`. Each row is added to the README tables, which
`test_mock_scenarios.py` recomputes.

Messages:

- **M13**: a portal PO forwarded from a Sales address on the seller's own
  domain. The buyer is named in the document → `customer_unknown`.
- **M14**: an RFQ forwarded by a manager.
- **M15**: a PO from an unknown domain whose buyer matches no customer → routed
  `customer_unknown`.
- **M16**: an image-only PDF PO → routed `attachment_unreadable`.
- **M17**: a sample request → routed `sample_request`, sent by the customer
  with no NOC.
- **Design replies**: one per RFQ, sent from a fictional internal Design
  address and quoting the YCBG number, with BP code, spec no. and copper
  kg/km. One more quotes a YCBG number that matches nothing.
- A PO that was keyed straight into Bravo (present in `bravo_orders.json`)
  and is now re-sent → `duplicate_po` against the Bravo export.
- One long intra-group PO: at least 10 sheets and 60 lines.
- A PO whose printed TOTAL disagrees with its lines, and a multi-sheet PO
  that skips a line number → `line_total_mismatch`.
- An RFQ missing a quantity → `rfq_incomplete`.
- A description starting with `=` (ticket 06's formula test).
- A PO in another currency than its quotation, and one with an unknown unit.
- An Excel PO with a hidden row and a hidden sheet holding a line →
  `value_uncertain`.
- A PO from the temporary-code customer → `customer_temporary`.
- A complaint about a delivered lot → routed `complaint`.
- One message whose mail-auth result is not `pass` → `sender_unverified`.
  Every other message passes.

With these, every order finding code in the spec and every routing reason
except `other` has a message that raises it (`revision_without_base` by
processing M07 before M04).

Data:

- `Customer` gains:
    - `sales_pic`: a persona's sign-in email, e.g. `an.nguyen@alpha.local`;
    - `status: official | temporary`, with one customer temporary;
    - `confirmation_channel: email | portal`, with one customer on portal.
- `Compliance` gains `denial_list_checked_on: date | None`.
- `InboundMessage` gains the mail system's SPF/DKIM/DMARC results.
- `bravo_orders.json` is the mock 12-month Bravo export, plus the open-YCBG
  list. The catalog port gains `orders_for_po(scope, customer_code, po_no)`,
  `orders_since(scope, since)` and `open_ycbg(scope)`.
- Every `SalesCatalogPort` read returns the snapshot's `as_of` beside its
  data.
- `configs/policies/sales_pricing@1.0.0.yaml` (MOCK, fictional numbers):
    - copper adder per LME band;
    - a floor margin;
    - freight per incoterm and destination.

    It has a Pydantic schema in dw_sales. It holds no approval matrix: which
    price or discount needs which approver is owed by Proterial
    (requirements doc §4 item 5). Until then any holder of
    `sales.quote.approve` other than the pricer approves, and ticket 12 adds
    the matrix here when it arrives.

Corrections:

- Relax the oracle's "every sender is a customer contact". M13–M15 break it
  on purpose.
- The item vocabularies (`Uom`, attribute enums) belong to the mock. A Bravo
  adapter maps values through an anti-corruption layer, and an unknown value
  becomes an unmapped attribute or a `uom_mismatch`, never a load failure.
- `FISCAL_YEAR_START_MONTH` moves to `sales_order_rules`
  (`fiscal_year_start_month`).
- Fixture and catalog validation errors name the record id and the field,
  never the value: today `catalog.py` prints contact addresses (G32, spec
  decision 8).

Acceptance: every new message and record is read through the ports, and its
README row is recomputed by the test.
