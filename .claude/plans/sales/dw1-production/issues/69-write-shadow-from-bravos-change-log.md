# 69 — Shadow for the Bravo writes, from Bravo's own change log

Status: in-progress (2026-11-25): designed; waiting on script 09 (UAT change log, local) to measure what the log holds

## Why

Đạt, 2026-11-25: DW enters every Bravo entry Sales made (ticket 68); "đưa
shadow cho lệnh ghi vào kế hoạch rồi làm luôn". Re-implementing how Bravo
saves is the risk: DW reuses Bravo's database logic (triggers, procedures)
and its screen rules as data (the runner, ticket 59), and writes its own
interpreter only. Shadow proves the interpreter on real saves before a write
kind is ever on.

## What was found (2026-11-25, the production schema)

Every save of a document is logged by Bravo's own trigger
(`DML_<table>_ChangeLog`, generated by `_CreateTriggerLog`) into
`<db>_Log.dbo.<table>$0`: the screen and its command word
(`__$CommandKey`, `__$CommandKey0`), I/U/D, the Bravo user, the time (UTC),
the session (one save), the update mask, and `__$Value`: XML of the new
values of the columns updated, then their old values (an insert: the new
row; a delete: the old row). So no person has to repeat a save: the log
holds every save Sales made, back as far as it is kept.

## Design

- **Read**: the gateway's read login reads the log tables of the screens DW
  writes (`B30BizDoc$0`, `B30BizDocDetailSO$0`, later RQ, SQ) past a cursor.
- **Rebuild**: one save = one session id on one document; the line as it
  stood before is today's row with the save's old values put back (only for
  the newest save of a document, so no later save hides it).
- **Replay**: the runner loads the before state, types the columns a write
  kind types (a date, a quantity; found as `testing/replay.py` finds the
  person's edits), plans the save with the template's guards, and compares
  its columns with the save's new values, column by column.
- **Record**: per save, the write kind, agrees / differs (column names only,
  never a value) / undecided (the rule the runner refused), in the gateway's
  database under the tenant's RLS; counts per kind on the gateway's page.
- **Gate**: a write kind is switched on in production only after a run of
  shadows with no difference (the count is the tenant's to set), beside its
  UAT acceptance (ADR 0027 decision 7).

3. The read login granted SELECT on the log tables (script 08).
